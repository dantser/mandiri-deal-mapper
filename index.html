Исключено — крупные сделки

Этим сделкам банк требует Underlying Document Code. Признак берётся из флага крупной сделки в Bitrix (на реальной выгрузке он совпал с поведением банка один в один), а если колонки флага нет — по оценке суммы выше ≈22 500 USD (порог LLD/Bank Indonesia — 25 000 USD, берём с запасом на погрешность курса). Сам код документа выдаёт не Bitrix, а KOPRA: Transfer → Underlying Document, где документ заводится и ждёт одобрения банка. Поэтому такие сделки не попадают в файл — проведите их вручную, приложив документ.

Результат

Таблица ниже — для проверки глазами (переименованные поля). Для загрузки в MANDIRI используйте кнопку «Скачать файл для банка» — она собирает отдельный файл ровно в 73 позиции формата Separated, без заголовка, с маркерами M/E, и подставляет дефолты банка (SWIFT Method=SPI, Purpose of Transaction=2670 и т.д.) там, где банк реально требует значение, а не только там, где это формально обязательно по спецификации. Колонка Customer Reference — название сделки, показано только для сверки строк: в банк оно не уходит (в эталонном платеже Transaction Reference пустой). Запятые в текстовых полях (разделитель полей в файле банка) заменяются на пробел автоматически, а адрес длиннее 35 символов сам переносится в Address 2 и Address 3 — в таблице показаны уже готовые значения. Красным — не хватает обязательного поля. Страна банка получателя сверяется со справочником MANDIRI (247 значений, снят с формы банка): известные варианты написания приводятся к написанию банка автоматически (жёлтым), неизвестные помечаются красным — банк такую строку отклонит. Код банка (SWIFT) банк проверяет по своему справочнику уже на своей стороне.
Как это работает

Берёт CSV-выгрузку сделок из Bitrix24 (воронка «Контракт», стадия «Набитие платежа в БК»), переименовывает поля по маппингу MANDIRI, добавляет служебные константы и собирает итоговый файл ровно в 73 позиции формата Separated — готовый к загрузке в форму «Multiple Transfer by File Upload». Всё считается в браузере — файл никуда не отправляется.

01Переименование полей Bitrix → имена полей MANDIRI CSV (Separated)
02Добавление служебных констант и подбор дебетового счёта VELMONT по валюте платежа
03Проверка обязательных полей и страны банка по справочнику MANDIRI, перенос длинного адреса в Address 2/3; сделки, которым нужен Underlying Document, исключаются отдельным списком
04Сборка файла для банка: все 73 позиции по спецификации, без заголовка, маркеры M/E

Underlying Document Code

Код выдаёт сам банк: KOPRA → Transfer → Underlying Document (Pending Bank Approval → Approved), в Bitrix его нет. Порог — 25 000 USD (LLD/Bank Indonesia), а не 100 000, как читалось из спецификации: реальная загрузка 21.09.2026 показала, что записи до ≈16 800 USD экв. проходят, а запись на ≈28 700 USD экв. требует документ. Исключаем по флагу крупной сделки из Bitrix, запасной вариант — оценка от 22 500 USD (порог с запасом на курс).

Курсы зафиксированы на (xe.com, mid-market) — только для отсечки порога, не для платежа. Со временем устареют, обновляйте вручную.

Обработка полностью локальная — CSV не покидает ваш браузер.
